# 蒸馏：AI 不缺智商缺纪律——Harness 工程化实践

**作者：** 杜学友  
**核心命题：** AI Coding 瓶颈正从「模型能力」转移到「流程工程」——模型已足够聪明，但不稳定；稳定性必须由外部框架供给。

## 一句话结论

> 对付 AI 的不确定性，**堆 prompt 是负债，做框架才是资产**。

---

## 核心架构：harness 三层设计

| 层级 | 内容 | 原则 |
|------|------|------|
| **常驻入口** | CLAUDE.md + CLAUDE.local.md | ≤8K，只放角色+触发规则 |
| **原子规则** | rules/（7个） | 每条规则 = 一次事故的墓志铭 |
| **按需上下文** | context/（10个） | 打官司时才搬弹药，用完即释放 |

---

## Agent 角色分工（薄主会话）

- **dispatcher**：交通警察，只读 `state.json` 返回"下一步调谁"，不管业务
- **orchestrator**：会议秘书，只合成三角色观点，不管调度
- **三角色并行**：requirement-analyst / tech-architect / quality-guardian，各写各的观点段，互不污染
- **主会话**：退化成一个"什么都不想、只执行 dispatcher 指令"的纯执行器

**三条铁律：**
1. 主会话只听 dispatcher
2. 职责隔离 + 工具受限
3. 上下文 ≤8K

---

## 四阶段演进（踩坑路线图）

```
拿来主义 → 重prompt约束 → 减负+分层加载 → Agent调度编排
  (oh-my-claudecode)   (全塞进CLAUDE.md)  (分层加载)      (dispatcher状态机)
       ↓                    ↓                 ↓                ↓
     天花板             三天后崩了         长程会话遗忘      最终架构
```

**核心教训：**
- prompt 约束 = 说服，不是强制。模型"理解"了规则 ≠ "遵守"了规则
- 把「有状态的流程」硬塞进「无状态的对话窗口」，本质是用错工具

---

## 为什么选文件交接而非 Workflow / Agent Team

| 机制 | 判定 | 硬伤 |
|------|------|------|
| **Workflow** | 不适合做控制平面 | 超时无法区分失败/被杀；无 askUser 原语；跨 session 不可续 |
| **Agent Team** | 不适合严格工序链 | 松散协调无确定性；状态散落；SendMessage 是通知不是阻断 |
| **dispatcher + 文件交接** | 适合有状态工序链 | 天然持久化 + 可审计 + 强一致性 |

---

## 稳定性支点：门禁外置

**两条铁轨：**
1. **G1–G8 门禁墙**：确定性 Python 函数检查产物、编译、单测，任一 FAIL 阻断退回
2. **hook 拦截**：工具调用执行前拦截，状态文件只允许编排层 agent 写

**核心原则：** 流程强制执行必须从 LLM 推理中外置到确定性基础设施。fail-closed（默认拒绝）。

---

## 评测平台：把流程当被测对象

**核心理念：** 评测平台是**评估者**，不是执行者。只检测节点是否走完，绝不替它执行。

**七维评分（100% 确定性，零 LLM 调用）：**
- 流程完整性 22%、代码正确性 22%（权重最高）
- 防注水：用 `amaven + jdk` 真编译、真跑单测，对比 AI 自报与真实结果的"诚实度差距"

**关键洞察：** 原始 token 消耗仅解释 agent 成功率方差的 R²=0.33~0.42，而验证反馈质量达 R²=0.94~0.99。

---

## 关键数据

- **上下文管理**：Stanford "Lost in the Middle" 证明 LLM 注意力呈 U 型分布，中部信息准确率显著下降
- **Token 效率**：NVIDIA RULER 发现声称 32K+ 的模型仅半数在该长度保持可靠性能
- **VikingMem 反直觉发现**：16.82% Token 留存得分 75.80，朴素 RAG 100% 留存仅 63.81——更少 token + 更智能组织 > 全量保留

---

## 可迁移模式

> 任何「能力够强但输出不稳定、且过程可观测」的 AI 工作流，都可以工程化：给它**分层的约束**、**外置的状态**、**确定性的评分**，让每一次改动都能被证明是进步还是退步。

**边界：** 依赖「过程可观测」——如果中间产物无法落盘（如纯创意生成），这套打法失效。
